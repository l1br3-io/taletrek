## Native track · Effort 5 (`ios-app`) · 2026-10-17

**The kernel crosses to the iPhone** — one effort, full Android parity, vertically sliced so every slice ends installable: the FFI surface is consumed unchanged plus exactly one additive wrapper, `decode_segment` (AVFoundation cannot decode OGG/Opus, and decode decisions stay in Rust — the kernel-decides discipline; m4a legacy segments are a documented v1 fail-skip). **Linking:** UniFFI Swift bindings are generated on the Linux host and checked in under `ios/TaleTrek/FFI`; Xcode never invokes Cargo (`just ios-kernel`/`ios-bindings` mirror the Android recipes) — the kernel rides as a pair of static libs (`aarch64-apple-ios` + `-sim`) vendored beside the sherpa `SherpaOnnxC.xcframework`, in a hand-rolled checked-in `.xcodeproj` whose six-trap ledger (group-relative paths, `module.modulemap` discovery, arm64-only sim slices, `SOURCE_ROOT`, `ENABLE_TESTABILITY`, runner-image drift) is paid and recorded. **Playback honors the Android contract verbatim** — kernel owns sequence and position, platform owns audio time: `AVAudioSession` .playback/spokenAudio, `AVAudioEngine`/`AVAudioPlayerNode` per segment at the PCM's native rate (mainMixer converts — the no-resample stance), Now Playing + remote commands at chapter granularity, route-change unplug pausing *through* the kernel; the same-key race closes on engine generation epochs plus the bridge's pending-load window. **The app:** the reader (follow/defer scroll, jump-to-chapter, the locked outline design, position restore from a one-JSON-file `PositionStore` keyed by `position_storage_key`), the library (live search, share/export, voice-aware convert), the voices screen (download/delete/select parity), and — the phone becomes a processor — the **progressive `SynthEngine`**: picking a document submits the full audio job immediately, the text bundle lands now, playback starts while the store fills horizon-first at the playhead, relaunch resumes; `FirstRunTest` owns fresh-install → download → convert → play, green against the real CDNs. Storage mirrors Android bit-for-bit (Application Support `books`/`voices`/`espeak-ng-data`, no database); conversion is foreground-only v1 with clean cancel on backgrounding. **Verification, two machines:** a lean `macos-15` CI job (kernel cross-build + SwiftLint + non-CDN simulator suites + the bindings drift guard) proved the loop early; when Actions went billing-blocked account-wide (~09-23, every job dead pre-start), the full gate moved to the local Mac — same bar, different host: kernel cross-build both targets + xcframework, 81 app-hosted unit + 6 UI tests on the iOS 27 simulator (Xcode 27), SwiftLint clean, zero bindings drift (2026-09-23 gate). **Release:** the signed-IPA workflow job ships with the effort — dry runs archive the simulator destination ad-hoc (Xcode 27 killed ad-hoc device archives; two latent job bugs caught by the local dry-run), tag pushes archive device + `DEVELOPMENT_TEAM`. Owed beyond ship: the certs session + real tag push (first full release run → signed IPA → TestFlight), the iPhone hardware checklists, and the CI billing fix. (`git log --grep ios-app`)

## Native track · Effort 4.9 (`progressive-reader-hardening`) · 2026-09-21

**Play-while-filling from every state** — a surgical recovery pass over `progressive-synth`, host-side Kotlin only (no FFI/kernel change). The shipped reader armed its fill session with a one-shot snapshot at open (`!audioPresent && jobActive()`), so opening a book in any other window — after a cancel, a failure, process death before the resume lands, before the submit's first phase — left the transport permanently inert behind "Text-only bundle — no audio to play."; worse, cancel/fail spent the pending marker and deleted the source, stranding minutes-to-hours of synthesized audio behind an unreachable Resume, and fill identity was process-wide (reading text-only A while B converted armed A's transport into an infinite buffer and steered *B's* synth horizon with A's seeks). All of it closes on one concept: a **`FillingBookMonitor`** — the single process-wide fill authority — derives `StateFlow<FillingBook?>` (path + Live|Paused) from the pending marker's shelf snapshot ∩ the shelf scan ∩ the service's job slot, snapshot-diffing the bundle that appeared since the marker was saved; a bounded rescan ticker bridges parse-to-bundle-landing so arming works even when no library screen is composed. On top of it: **reactive per-book arming** (the reader collects the monitor filtered to its book — arms whenever *this* book's fill goes live, reanchoring at the rendered position, sticky through the seal; the one-shot sample is deleted), **per-book `keepWaiting` + `ACTION_REANCHOR` routing** (A never buffers on B's job, A's seeks never steer B's horizon — pinned on device), **the segment store registered at process start** (`PlaybackService.onCreate`, one dir definition shared with the import wiring — the FFI player's text-only gate passes before any job has ever run, so reads reach `NotReady`/`Missing` and the app decides), and a **terminal-policy split** (Done spends marker + source as before; Cancelled/Failed stamp an additive, tolerantly-read reason and keep both — a relaunch auto-resumes only an unspent marker, while the reader's Resume and the library row's new inline Resume button work the manual door, un-stamping the marker as the job goes live again). The reader's buffering line now mirrors the live job through one shared copy derivation ("Downloading voice 12 of 63 MB", "Preparing audio · 24 of 210 paragraphs" — same mapping the notification and convert card render), and a failed fill's affordance reads "Retry" instead of "Resume". Gates: workspace clippy/tests untouched-but-green, JVM suites + ktlint green, **42 on-device instrumented tests** on the G31 emulator including the new `FillStatesTest` (open-before-submit arms and plays; cancel keeps material, relaunch never auto-resumes, manual resume seals with no voice re-download; a foreign text-only book stalls honestly while another converts) and `HardeningTest`'s keep-materials cancel invariant. (`git log --grep progressive-reader-hardening`)

## Native track · Effort 4.8 (`progressive-synth`) · 2026-09-18

**Books that play before they finish** — the product goal moves from whole-book wall time (bounded by hardware, never controllable) to **time-to-first-listen + never stalling**. Two phases over the same kernel. **Phase 1 (behavior-neutral scheduling wins, benchmarked on the reference book in `bench.md`, preserved in the progressive-synth effort record):** the synth pool's work unit drops from whole paragraphs in contiguous chunks to **sentence-chunk tasks** (assembly stays per-paragraph, cache-key parity byte-identical), ordered **LPT** (longest first) over a **shared runner pool** (N persistent workers, one runner each — same memory envelope), plus a **dedup pre-pass** that synthesizes each distinct cache key once. Makespan −7%/−10% (j2/j4), pool efficiency +7–9 pp, reference book −7.3% wall — and the run found a real bug (wrapper runners silently dropping the 120-char chunk cap since desktop-synth-gui). **Phase 2 (the product story):** a global **content-addressed segment store** (`<cache>/taletrek/segments`, atomic writes, LRU-by-mtime), a new **`PipelineVariant::Progressive`** — the text-only bundle lands *immediately* (the book exists from second one), synth fills the store **horizon-first at the playhead** (anchor-ordered, movable live via `set_anchor`; ≥ 30 s of audio at the resume position = `Playable`), and drain **seals** into a standard `.taletrek` byte-compatible with batch output. Cancel or kill mid-fill keeps a valid text bundle + a reusable store; a resubmit **skips existing keys** (progress fast-forwards, pre-seeded durations parsed from the store) — re-converting a finished book+voice seals near-instantly. **Android** imports all go progressive: the state machine grows `converting → filling → sealed`, the reader **plays while filling** (`NotReady` buffers with a spinner, a dead job surfaces a resume affordance — never a silent skip; opening at position and seeking re-anchor synthesis at the playhead), library rows show fill progress, and relaunch after process death **resumes from the pending marker + store** anchored at the stored reading position. Batch `Full` stays byte-for-byte for desktop/CLI; the FFI surface is additive and iOS-ready (`read_segment_progressive`, progressive config + anchor, `set_segment_store` — one post-freeze addition, flagged for review). *Post-ship tuning (2026-09-19):* `PLAYABLE_SECONDS` 30 → 15 s (halves warm-run time-to-first-listen; the horizon scheduler absorbs the earlier fire) and the library renders **one row per book** — the convert card folds into the filling book's row once it lands (cancel lives in the row's menu; the card stays for pre-row phases and terminal feedback). Same-day fix: `VoiceStore.setSelected` now mirrors the write into the selection snapshot synchronously — the DataStore collector ran on `Dispatchers.IO`, so an immediate `selectedSnapshot()` (import submit, tests) could still read the pre-write value. Gates: workspace + JVM suites green; **39 on-device instrumented tests** including the two new progressive e2es — `ProgressiveListenTest` proves playback advances while the job reports < 100% and survives the seal, `ProgressiveResumeTest` proves a re-submitted run seals with no voice re-download and no re-synthesis. Real-phone legs (thermal/battery while filling+playing, unplug-during-fill, on-device kill/relaunch) are **device-gated and owed**, recorded in the task file. (`git log --grep progressive-synth`)

## Native track · Effort 4.7 (`android-hardening`) · 2026-09-16

Three surgical closes over the shipped Android app — no new capability, no kernel change. **Unplugging headphones now pauses the book** like every audiobook incumbent: a `NoisyAudioRouter` in `PlaybackService` registers `ACTION_AUDIO_BECOMING_NOISY` exactly while playing (the focus gate's shape — idempotent on the playing boundary, never a leak, released on destroy) and routes it through the kernel's `userPause`, so notification + reader agree and one tap resumes at the recorded offset; re-plug never auto-resumes (the focus policy's stance, verbatim). The stale "audio-focus handling is OFF for now" builder comment — written before that hardening shipped — now tells the truth: built-in focus is off *because* `AudioFocusPolicy` + noisy routing own interruption, all kernel-routed. And the **outline reads like the incumbents'**: the locked reader-page design (ios-app spec, 2026-09-15) backported onto `OutlineSheet` — numbered rows with muted prefixes, the current chapter accented with a trailing "Now reading" marker, an honest "Chapter *n* of *N*" header line, and the sheet opening pre-scrolled to where you are; the derivations are pure helpers (`outlineHeader`, `outlineRow`) so the JVM suite owns them, and the tap path stays `jumpToChapter` (one kernel event). Eleven new JVM cases over recording fakes (the receiver's registration gate + churn + action mapping, the outline derivations), ktlint clean, no ExoPlayer-internal pause introduced. The human hardware checklist (unplug-pause on device, battery/thermal at sustained pool=2 synth, Files-app walkthrough, long-TOC pre-scroll) is **explicitly deferred — device-gated and owed**, recorded in the task file. (`git log --grep android-hardening`)

## Native track · Effort 4.6 (`android-instant-listen`) · 2026-09-14

**File in, audio out, zero decisions** — and the first-run promise actually holds now. Two things were wrong with the shipped import flow: full synthesis was **broken on a fresh install** (the pipeline never acquired espeak-ng-data, so the job died at sherpa construction — every instrumented test had been quietly calling a manual prerequisite first), and the app made you **configure it before doing its one job** (a Listen/text-only dialog, Audio/Text badges, a voice prerequisite nudge). Both gone. The fix is kernel-side — the pipeline job itself ensures espeak-ng-data after resolving the voice (same cache-or-download seam, same progress events, a new typed `espeak` failure kind), so every host (Android now, iOS next) is first-run-correct with zero prerequisite code. The UX is now one flow: pick or share a document → the full audio job starts immediately (first run downloads voice ~63 MB + espeak ~9 MB inside the job with honest "Downloading x/y MB" progress) → the book lands in the library and plays. No dialogs, no mode choice, no voice setup; text-only `.taletrek` bundles from desktop/web still import via `+` and read with transport disabled + neutral copy. **`FirstRunTest`** owns the fresh-install → convert → play story end to end on a device (isolated dirs, real CDNs, real Media3 playback) — the acceptance proof this flow never had. (`git log --grep android-instant-listen`)

## Native track · Effort 4.5 (`android-pipeline`) · 2026-09-14

**The phone becomes a processor** — files in, audio out, no desktop anywhere in the loop ([ADR-0016](docs/adrs/0016-on-device-pipeline-android.md): the player-only scope and VISION's "later, once the kernel is proven" deferral are spent). Share a PDF from the Files app (or pick any EPUB/PDF/DOCX/HTML/MD/TXT from the in-app **Convert** action) → a voice gate offers *Listen* (synthesizes on-device) or *Import text-only* → the **`SynthService`** foreground service converts with a live progress notification (phase, paragraphs n/total, voice download MB, cancel from the shade) that survives screen lock → the finished book lands in the existing library and plays through the existing reader with lock-screen controls. No voice downloaded yet? *Listen* fetches the curated default (~60 MB, bit-for-bidentical URLs to desktop/web) or you import text-only and read it now, synthesizing later over the same entry. Re-importing the same document is **idempotent by construction** — deterministic content-derived book ids mean one shelf entry, and a later audio import overwrites the text-only one. A new **Voices** screen manages the 8-voice curated catalog (download with progress, delete, select — selection persists and drives every import).

The structural deliverable is **`crates/worker::pipeline`** — the convert orchestration left the desktop's egui-land and became a cancellable, observable kernel object (`PipelineJob`: parse → deterministic id → synth+stamp → atomic write; per-paragraph cancel that can never half-write a book; `PipelineEvent` progress). `crates/ffi` grows the additive surface — `PipelineHandle` + `PipelineObserver` (callbacks from rayon threads, validated on-device), the voice catalog/cache wrappers, and espeak-ng-data acquisition in the kernel — all platform-neutral and **Swift-ready for `ios-app` unchanged**. The `.so` grows accordingly (**+27 MB arm64 / +31 MB x86_64** from onnxruntime + sherpa; measured, under the ask-first line; the universal APK is flagged in release notes). Emulator datapoints: **~211 paragraphs/min at pool=2 (~1.7× pool=1)**, 0.6 s/paragraph, +20 MB RAM for a 6 MB source; battery/thermal hardware numbers pending the manual pass. Gates: workspace + android JVM + **36 on-device instrumented tests** (six-format matrix, cancel/error hardening matrix, real CDN voice round-trip, selection-driven manifests) all green.

## Native track · Effort 4 (`android-app`) · 2026-09-09

The kernel crosses to a phone — the pivot's payoff. **`crates/ffi`** (`taletrek-ffi`) gives the read-side core its foreign surface: UniFFI proc-macro wrappers over `crates/reader`/`crates/synth` **default features only** (no sherpa, no libopus — the `.so` stays 3.4 MB), exposing `openBook` (manifest + chapter text → navigable book; audio entries never scanned), `readSegment` (the streamed single-entry disk read), and `TrekPlayer` — a UniFFI object holding `BookIndex` + `Mutex<PlayerState>` so the by-value enum never crosses. Zero new logic beyond the sanctioned restore-validation branch; the generated Kotlin is **checked in** and regenerated by `just android-bindings` (Gradle never invokes Cargo). (`git log --grep android-app`)

**`android/`** is the player the whole effort existed for — hand-rolled Gradle + Compose + Media3, single activity (library ⇄ reader via Navigation Compose). The library is manifest-driven (no database): `books/` scanned through the kernel, SAF copy-on-import with kernel-validated staging (a rejected pick leaves zero residue), delete clears file + position. The reader is desktop-parity: per-chapter LazyColumn text pane in the ported desktop-ux-refresh two-theme tokens (hex-for-hex, serif story / mono machine), outline bottom-sheet, click-to-seek, spoken-paragraph highlight in identical frames with drag-defer/auto-resume follow scrolling, and a six-forward transport bar that goes inert with an explanatory hint on text-only bundles. **The Jog bar** is real: a Media3 `MediaSessionService` (foreground `mediaPlayback`) hosts one ExoPlayer over temp-file paragraph segments, the notification and lock screen expose play/pause + prev/next **chapter**, audio focus maps to kernel `userPause`s (never behind its back), corrupt/missing segments skip with a surfaced count while the book keeps playing, and positions persist through process death in DataStore keyed by the kernel's own storage key — re-open resumes at the paragraph, paused, never auto-playing. Sequencing owns zero Kotlin: every next/prev/boundary decision is a `PlayerState` transition; Media3 reports `ENDED` → `SegmentDrained{key}` and obeys `LoadSegment`.

Ship plumbing: `just android*` recipes (cargo-ndk kernel for arm64-v8a + x86_64, headless test gates, on-device suites), an additive CI job (cross-build + assemble + JVM tests + a bindings-drift guard), and a release job that attaches a **signed AAB + signed universal APK** to tag pushes (dry runs stay unsigned on the run; the landing page links the APK). Keystore creation + secret names live in `docs/releasing.md` § Android.

Tiers of the native track: **desktop shipped** — and the phone plays what it writes; `ios-app` (same `crates/ffi` surface, Swift target) follows.

## Native track · Effort 3.6 (`desktop-reader-page`) · 2026-09-08

The processor learns to read back what it writes — and the kernel grows its read side. **Read** on a finished job (or *Open bundle…* for any `.taletrek` on disk) opens the book inside the same window: chapter outline, serif text pane, and paragraph-synced audio through in-process `symphonia` OGG/Opus decode + a `cpal` output stream on a dedicated thread. The spoken paragraph highlights (accent frame that never reflows the text), the pane follows it while you read along and stops the moment you scroll elsewhere, paragraphs and outline entries are click-to-seek, and a scrub slider restarts the current segment at a decoded offset. Corrupt/missing segments skip with a surfaced count instead of stopping the book (the web reader's tolerance, kernel-owned now); text-only bundles read fully with a disabled transport that explains itself. Position survives restarts — saved on paragraph advance and on leaving the reader, keyed by the manifest's book id through egui persisted storage, so moving the file or re-voicing it keeps your place. Conversion keeps running underneath an open book: the queue executor and the audio thread coexist behind one-way channels. (`git log --grep desktop-reader-page`)

The structural deliverable is **`crates/reader`** — the read-side kernel core alongside `crates/parse`: `BookIndex` (manifest + chapter text → navigable model, per-paragraph segment keys from the *same* `cache_key` the writer used — reader and writer cannot drift, pinned by an anti-drift round-trip against real written bundles), the pure `PlayerState` sequencer (platform contract: **kernel owns sequence + position, platform owns audio time** — every transition total and defensive, stale completions absorbed, text-only books no-op), and `Position` (plain data + book-id keying; storage backends are per-platform). Zero UI/audio/hardware dependencies, UniFFI-shaped — Android (Media3) and iOS (AVFoundation) consume it unchanged in efforts 4–5; the desktop is the first consumer, not the owner. Both OGG/Opus lineages decode through one path (native encoder output and `--ffmpeg` bundles — the latter pinned by a committed fixture generated with the exact subprocess invocation).

Tiers of the native track: **desktop processor shipped** (effort 3) — now with its reader; `android-app` → `ios-app` follow.

## Native track · Effort 3 (`desktop-synth-gui`) · 2026-09-04

The kernel gets its face — and loses its external binaries. `taletrek-desktop` is now a windowed app: bare invocation (or `gui`) opens an egui/eframe shell where you drop or pick documents (`.epub`/`.txt`/`.md`/`.html`/`.docx`/`.pdf`, or a bundle), pick a voice from the curated catalog (downloaded on demand from HuggingFace, seeded-cache hit by default), and watch live per-paragraph progress as a FIFO job queue converts each source to a `.taletrek` beside it. Re-voicing an existing bundle is a second queue action (`<stem>.<voice>.taletrek`, input never clobbered); settings persist output dir, default voice, and worker count; failures render as one human sentence with Retry, and cancel is cooperative (a cancelled job can never half-write a bundle). The same binary keeps the full CLI — `parse`/`synth`/`resynth` — interface unchanged. (`git log --grep desktop-synth-gui`)

The engine swap that makes it distributable: TTS and encode now run **in-process** — `SherpaRunner` (feature `sherpa`: the official k2-fsa crate, statically linked from prebuilts — no cmake/libclang/system onnxruntime; Piper voices today, Kokoro via the same API later) and `NativeOpusEncoder` (feature `native-encode`: vendored static libopus + pure-Rust OGG mux). The CLI default flips to native; `--piper`/`--ffmpeg` remain explicit subprocess overrides for parity testing — cache keys are text-derived, so bundles from either engine are interchangeable by construction (pinned by the parity test). The engine traps live inline in the module docs (`sherpa_runner.rs`: tokens.txt derivation, espeak-ng-data, ONNX metadata stamping, ~212 MB per runner model; `opus_native.rs`: RFC 7845 mux shape, resampling into libopus's native rates). Distribution ships with it: a tag push builds the release matrix (Linux x86_64 glibc first-class, aarch64/Windows/macOS best-effort), smoke-tests the Linux artifact headlessly, and attaches `taletrek-<version>-<target>` downloads to the GitHub release — the whole loop runs on a clean machine with zero native deps installed.

Tiers of the native track: **desktop processor shipped** (this) — the reader consumes its output; `android-app` → `ios-app` follow.

## Native track · Effort 2 (`kernel-parse`) · 2026-08-31

The kernel learns to ingest. New `crates/parse` (`taletrek-parse`) turns a source document — EPUB, TXT, HTML, Markdown, DOCX, PDF — into cleaned, chaptered plain data (bytes in, `ParsedBook` out, UniFFI-ready), and the desktop CLI grows `parse` (source → text-only `.taletrek`) plus the chained one-command `synth --input book.epub` (source → full audio bundle). This closes the pivot's accepted interim gap: until now, nothing converted ebooks into bundles. (`git log --grep kernel-parse`)

Cleaning is the M4 structural filters (URLs, images, footnotes, page numbers) applied **at parse time** — bundle paragraphs are canonical clean text, with the cross-app idempotence invariant pinned from both Rust and TS ([G30](docs/gotchas.md#g30)): whatever the reader re-derives must not change a parsed paragraph, or its audio cache key breaks. PDF chapters are ADR-0008 tier-1 only (embedded outlines, no heuristics); TXT chapters split on standalone `CHAPTER 7`-style lines only — both ADR-0008's prose false-positives stay in-body. The bundle `sourceFormat` vocabulary grows `html`/`docx` (additive, v1 unchanged); MOBI stays deferred (typed error, pinned by test).

## Off-device synth track · Tier 3 completion (`server-hosted-spa`) · 2026-08-29

Effort 5 makes the SPA a **live client of the personal server** — one codebase, two deployment shapes (ADR-0014): the unchanged offline-first PWA, and the same SPA **hosted by the server** with server-side persistence and native processing. Deploy the Docker image (it now builds the whole stack — server binary + SPA — in one `docker build`), open the origin, sign in with the token, and get the full TaleTrek UX: upload an EPUB, close the tab (synth keeps running on the server), reopen, press play. The server-rendered operator panel is gone — the hosted SPA is the UI. (`git log --grep server-hosted-spa`; ADR-0014)

How the shape picks itself: a boot probe of same-origin `GET /api/session` — authed → server mode (library, synth, playback all server-backed); 401 → the cookie login gate; unreachable → the standalone local-mode PWA, byte-identical to before. New server surface: `GET /api/session`, `GET /api/books/:id/chapters` (lazy chapter explode), `GET /api/books/:id/audio/:key` (content-addressed Opus segments), `PATCH /api/books/:id/progress`, `GET /api/voices`, `POST /ui/logout`. The service worker is scoped network-only for `/api/*` + `/ui/*` (no stale-library masquerade, no post-logout redirect loop) with explicit offline states ("Can't reach your server" / amber offline banner). Hosted settings swap the on-device voice manager for the server voice picker + logout; upload applies the cleaning config before the bundle write so parse text, reader text, and audio keys agree. Deploy guide: [`docs/deploy-digitalocean.md`](docs/deploy-digitalocean.md). Safari/Opus hosted playback remains a hardware-gated follow-up.

Tiers now reachable: **(1)** SPA alone · **(2)** SPA + Desktop · **(3)** SPA + personal server — **live-hosted** (this; bundle exchange with the server still works).

## Off-device synth track · Tier 3 (`personal-server`) · 2026-08-24

Effort 4 ships the **personal server** — `taletrek-server`, a Docker-first Rust/axum library server that turns synthesis into an always-on service ("close every device, synth keeps going"). Books upload as `.taletrek`/`.taletrek-lib` (idempotent upsert by bundle id), synth/resynth run as background jobs with progress polling, full bundles download back to the SPA; a server-rendered, JS-free operator UI (cookie login) covers the same loop in a browser. Shared cores were extracted into `crates/worker` (voices + rayon pool + manifest stamping) so desktop and server stamp through one path. (`git log --grep personal-server`; ADR-0013)

Ship-hardening landed with it: manifest voice consistency on server synth (the manifest names the voice segments are keyed under — the format's implicit key contract), one-job-per-book + delete-vs-job guards (no mid-job resurrection), atomic uniquely-temp'd writes, login rate-limiting, security headers (CSP/nosniff/DENY/no-referrer), zip decompression caps (256 MiB/entry, 1 GiB/archive — closes the nested-bundle bomb), piper tarball sha256 verification, `.onnx` download size sanity band, the curated voice-config URL fix (HF hosts `<voice>.onnx.json`), and loopback-pinned dev binds.

Tiers now reachable: **(1)** SPA alone · **(2)** SPA + Desktop · **(3)** SPA + personal server (this).

## M13 — Whole-Book Streaming AI Transform · 2026-07-20
