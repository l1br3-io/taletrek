# PRD: M0 — Foundation

> **Status:** Ready to implement.
> **Companions:** [`../../VISION.md`](../VISION.md), [`../../ROADMAP.md`](../ROADMAP.md), [`../spikes/piper-wasm.md`](../spikes/piper-wasm.md), [`../adrs/0001-piper-gpl-licensing.md`](../adrs/0001-piper-gpl-licensing.md).

## Objective

Ship a functional **Progressive Web App shell** for TaleTrek that installs on iOS/Android, boots offline from first load, persists data durably across restarts, and presents the three core views (landing, reader placeholder, settings). This milestone delivers no feature logic — it is the foundation every subsequent milestone (upload, TTS, playback) builds on.

**User story:** *As a first-time visitor, I can open the TaleTrek URL, add it to my home screen, and reopen it days later — offline — to find the same UI and my settings intact.*

## Code Style

Follows `.opencode/tech/typescript/patterns.md` + `react/patterns.md`. Highlights:

- **Strict TS**, branded IDs (`type BookId = string & { readonly __brand: 'BookId' }`)
- **Container/presentational split** — containers own data; components are pure props
- **Context for low-frequency state only** (settings, theme) — never for playback state
- **Variant types** for async/machine states: `{ type: 'idle' } | { type: 'loading' } | ...`
- **Define the contract (interface) before implementing**
- One real snippet beats three paragraphs — see the tech patterns files

## Testing Strategy

- **Unit/component:** Vitest + Testing Library in `web/src/**/*.test.tsx`, co-located. Cover: db round-trip, settings persistence, route rendering.
- **Runtime/PWA:** chrome-devtools MCP (already configured) — verify SW registration, offline reload, zero console errors, Lighthouse PWA installable.
- **Coverage target:** logic modules (`lib/`, `hooks/`) at >80%; UI routes smoke-tested.
- **No E2E framework yet** — MCP + manual for M0; add Playwright if M1+ demands.

## Boundaries

- **Always:** `pnpm typecheck && pnpm test && pnpm lint` green before considering a task done; validate inputs at module boundaries; define interfaces before implementing.
- **Ask first:** adding a dependency; changing IndexedDB schema version; modifying CI config; touching `vite-plugin-pwa` strategy.
- **Never:** commit secrets or large binary models; disable strict TS; delete a failing test to make CI pass; bundle Piper into the app at M0 (deferred to M2).

## Success Criteria (testable)

1. `pnpm dev` boots; `pnpm build` produces `web/dist/`.
2. Lighthouse PWA audit = **installable**.
3. App loads **fully offline** after first visit (SW caches shell).
4. IndexedDB write/read **survives a hard reload**.
5. A setting changed in `/settings` **persists across reload**.
6. Routes `/`, `/reader`, `/settings` render; nav works; unknown path → 404 fallback.
7. `navigator.mediaSession` is feature-detectected (logged, no errors, no playback).
8. `pnpm typecheck && pnpm test && pnpm lint && pnpm build` all green.
9. chrome-devtools MCP run: **zero console errors**, SW registered, offline reload succeeds.

## Risks (tracked, not blocking)

- **Safari 7-day ITP eviction** — mitigated by `storage.persist()` + treating cache as re-hydratable. Validated in M5.
- **Piper engine viability** — de-risked by the parallel spike (Track B), not on M0's path.

## Out of scope (M1+)

File upload/parsing, TTS, audio playback, cleaning pipeline, library view, real Media Session playback, Piper integration.
