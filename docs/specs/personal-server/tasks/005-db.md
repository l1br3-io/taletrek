# Task 005: `db.rs` — rusqlite + migrations (books/jobs) + `Db` trait + `spawn_blocking`

**Description:** The SQLite persistence layer. Two tables — `books` (a mirror of each bundle's `BookMeta` for browse/listing without opening the bundle file) and `jobs` (synth/resynth lifecycle). All calls are sync `rusqlite`, wrapped at the call site in `tokio::task::spawn_blocking` by the HTTP/runner layers (this task's own tests call synchronously). A `Db` trait seam fronts the queries so the server's handlers are unit-testable with an in-memory stub — no real SQLite needed in HTTP tests. `books` rows are written by the ingest path (T6/T8); `jobs` rows by the synth runner (T9).

**Acceptance criteria:**
- [ ] `server/Cargo.toml` adds `rusqlite` (with the `bundled` feature so the Docker build needs no system SQLite).
- [ ] `server/src/db.rs` opens/initializes a single `rusqlite::Connection` at `<data_dir>/taletrek.db`, runs idempotent `CREATE TABLE IF NOT EXISTS` migrations on boot:
  - `books(id TEXT PRIMARY KEY, title TEXT, author TEXT, source_format TEXT, voice_id TEXT, audio_present INTEGER, chapter_count INTEGER, created_at INTEGER, updated_at INTEGER)` — mirrors bundle `BookMeta`; `id` is the bundle's `book.id`.
  - `jobs(id TEXT PRIMARY KEY, book_id TEXT, kind TEXT, voice TEXT, status TEXT, done INTEGER, total INTEGER, error TEXT, created_at INTEGER, updated_at INTEGER)` — `kind ∈ {synth,resynth}`, `status ∈ {queued,running,succeeded,failed}`.
  - Useful indexes: `jobs(book_id)`, `jobs(status)`, `books(title)`.
- [ ] A `Db` trait (in `db.rs` or a small `repo.rs`) declares the query surface used by later tasks: `upsert_book(BookRow)`, `get_book(id) -> Option<BookRow>`, `list_books() -> Vec<BookRow>`, `delete_book(id) -> bool`, `create_job(JobRow) -> job_id`, `update_job_status(id, status, done?, total?, error?)`, `get_job(id) -> Option<JobRow>`, `list_recent_jobs(limit) -> Vec<JobRow>`. The concrete `SqliteDb` implements it; an in-memory `Vec`-backed stub is provided behind `#[cfg(test)]` (or in a `test_utils` module) for handler tests.
- [ ] Typed row structs: `BookRow`, `JobRow`, plus a `JobStatus` enum (`Queued|Running|Succeeded|Failed`, serde lowercase to match the column) and `JobKind` (`Synth|Resynth`). Variant enums mirror the SPA's `{ type: 'loading' }` pattern (spec § Code style).
- [ ] `SqliteDb::open(path)` runs migrations + sets `PRAGMA journal_mode=WAL` (concurrent reads during a synth write) and `busy_timeout` (the runner writes from `spawn_blocking` while reads come from handlers).
- [ ] This task does **not** wire `Db` into the axum app yet (that starts in T7/T8); it only proves the layer in isolation.

**Verification:**
- [ ] `cargo build -p taletrek-server` clean; `cargo clippy -p taletrek-server --all-targets -- -D warnings` clean.
- [ ] `cargo test -p taletrek-server` green — `db.rs` `#[cfg(test)]` using `tempfile::tempdir()`:
  - [ ] open a fresh db → migrations create both tables; reopening is idempotent (no duplicate-table errors).
  - [ ] `upsert_book` then `get_book` round-trips every `BookRow` field; `list_books` returns all; re-`upsert_book` with the same id updates (idempotent upsert); `delete_book` returns true and the row is gone.
  - [ ] `create_job` → `update_job_status` transitions `queued → running → succeeded` (and a `→ failed` path carrying an `error` string + the paragraph index); `get_job` + `list_recent_jobs` return the right rows.
  - [ ] The in-memory stub `Db` impl compiles against the same trait (smoke-test one query through it).

**Dependencies:** T4 (server crate + `Settings.data_dir` exist; `data_dir` is where `taletrek.db` lands).

**Files likely touched:**
- `server/Cargo.toml` (add `rusqlite` bundled; dev-dep `tempfile` already implied)
- `server/src/db.rs` (new — connection, migrations, `Db` trait, `SqliteDb`, row structs/enums)
- `server/src/main.rs` (open the db on boot — minimal: construct `SqliteDb::open(&settings.data_dir.join("taletrek.db"))`, hold for later tasks; or defer wiring to T7. Keep main booting.)

**Docs:** A `/** GOTCHA */` on `spawn_blocking`: rusqlite is sync; every call from an async handler/runner must go through `tokio::task::spawn_blocking`, or the runtime stalls. Matches ADR-0013 "SQLite-default" + the spec's rusqlite-under-tokio risk.

**Estimated scope:** Medium–Large (schema + trait + stub + ~8 query methods + tests). If the trait surface feels unwieldy in build, split the `jobs` queries into their own task ahead of T9 — but keep books+jobs tables in one migration here.
